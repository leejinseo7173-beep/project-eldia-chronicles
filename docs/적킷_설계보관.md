### 두 가지 서로 다른 원인이 섞여 있다 — 구분해서 다뤄라

1. **진짜 밸런스 공백**: 마법사·궁수 주인공이 **노말에서** 전부 불합격.
   특히 망령 기사장전이 14~17턴까지 늘어진다(검사 6.56턴). 이건 실제로 고쳐야 한다.
   원인 가설 — 망령 기사는 고방어 물리 벽이라 마법 공략을 유도하는 설계인데,
   정작 마법사 주인공이 더 오래 걸린다. 직업별 계수·성물 스킬을 다시 봐야 한다.

2. **판정 기준 자체의 공백**: `PASS_CRITERIA`에 **난이도 보정이 구현돼 있지 않다.**
   작업계획 2부 §5는 "이지 = 수치 +15%p 여유 / 하드 = −15%p"라고 정했는데
   `simulator.js`의 기준표는 노말 기준 하나뿐이다. 그래서 하드가 전부 불합격으로
   나오는 것은 **적이 세서가 아니라 잣대가 없어서**다. 하드를 판정하려면 기준부터 만들어야 한다.

### 재개 시 작업 순서 (이 순서를 지켜라)

1. `PASS_CRITERIA`에 난이도 보정을 구현한다 (§5의 ±15%p).
2. `judgeAll`을 **주인공 3직업 × 난이도 3단계 = 9칸 격자**로 돌리는 헬퍼를 만든다.
   앞으로 밸런스 판정은 이 격자가 기본이다. 한 칸만 보고 "합격"이라고 하면 안 된다.
3. 육성 4축(M5)을 반영해 **3직업 전부** 기준선을 합격시킨다.
4. 그 다음에야 아래의 적 킷을 얹는다.

| 빌드 | sword | mage | archer |
|---|---|---|---|
| 기준선 | 100% 6.56턴 | **99%** 14.57턴 | 90% 17.57턴 |
| 암흑 주술사에게 물결 부여 | 100% 6.27턴 | **55% 35.13턴** | 100% 11.79턴 |
| 물결 제거 (그 외 전부 동일) | 100% 6.28턴 | **100%** 14.26턴 | 98% 13.41턴 |

역시 반격 세금이다. 주술사가 딜 액티브를 얻으면 반격을 안 맞고, 저화력 파티가 못 죽여 60턴 가드에 걸린다.
→ **채택: `e_dark_wave`는 상급 주술사(정예) 전용.** 이로써 id 충돌도 자연 해소되고, [정예변종] 검증이 요구한 "죽은 킷(`e_dark_bless`) 대신 광역 딜" 처방을 그대로 쓸 수 있다.

**§3-4 "마왕군 5종에 광역기 1개씩"은 3종(궁수·살수·기사)만 달성된다.** 병사·주술사 2종은 위 실측 근거로 제외했다 — 계획서 문구와 어긋나므로 사용자 승인이 필요하다(4장 참조).

```js
// ============================================================
// gimmicks.js — 보스 기믹 정의 (절대 규칙 3: 데이터 주도)
// 수치는 balance.js(gimmick), 판정 로직은 battle/logic.js. statuses.js와 같은 규약이다.
// ★ desc에 수치를 쓰지 않는다 (절대 규칙 2). balance.js에서 mult/charges를 바꾸면
//   화면 문구가 거짓이 되기 때문이다. descFmt에 balance 값을 끼워 조립한다.

//   현재 판정은 logic.js의 switch이며, 새 기믹 추가는 case 1개 추가를 뜻한다.
// ★ 기존 몹 id(skeleton_soldier·wraith_knight 등)에 gimmicks를 직접 달지 마라.
//   createBattleFromStage의 ENEMIES[id].gimmicks 폴백 때문에 그 몹이 나오는 모든
//   스테이지가 오염된다. 전용 id를 새로 만들거나 스테이지 층에서 부여할 것.
// ============================================================
export const GIMMICKS = {
  firstHitHalf: {
    id: 'firstHitHalf', name: '무쇠 각오', hook: 'incomingDamage',
    descFmt: '매 턴 처음 받는 피해 {pct}% 감소 (HP {hp}% 아래에서는 해제)',
    hint: '약한 일격으로 흘리고, 강한 일격을 뒤에 넣어라',
    icon: '쇠', color: 'skyBlue',
  },
};

// 화면 표시 문구 조립 — 수치의 유일한 출처는 balance.js다
export function gimmickDesc(id, C) {
  const g = GIMMICKS[id];
  if (!g) return '';
  return g.descFmt
    .replace('{pct}', String(Math.round((1 - C.mult) * 100)))
    .replace('{hp}', String(Math.round(C.activeAboveHpPct * 100)));
}
```

**⑤ 232행 `// ----- 데미지 계산 -----` 바로 앞에 신규 섹션 삽입**
```js
// ----- 보스 기믹 (작업계획 2부 §3-4) -----
// 데이터(gimmicks.js) = 정체성 / balance.js = 수치 / 여기 = 판정.

export function hasGimmick(unit, id) { return !!unit.gimmicks?.includes(id); }

// 반감을 소모하는 피해 종류. 도트는 '피격'이 아니다 —
// 화상 틱은 endPlayerPhase에서 플레이어 입력 없이 터지므로 인지도 계획도 불가능하다.
const MITIGABLE_KINDS = new Set(['hit', 'assist', 'counter']);

// 남은 반감 횟수 (순수 함수 — 예상 결과 패널이 이걸 그대로 쓴다).
// '매 턴'은 state.turn 하나로 정의한다. turn++는 startPlayerPhase(708행)뿐이고
// createBattle이 turn=1로 시작하므로 "아군 페이즈 시작 = 충전 복구"가 자동 성립한다.
// 리셋 코드를 따로 두면 생성·페이즈 시작 두 지점이 조용히 어긋난다.
export function firstHitGuardLeft(state, unit) {
  if (!unit.alive || !hasGimmick(unit, 'firstHitHalf')) return 0;
  const C = BALANCE.gimmick.firstHitHalf;
  if (unit.hp <= unit.stats.maxHp * C.activeAboveHpPct) return 0;   // HP 절반 아래면 해제
  const s = unit.gimmickState.firstHitHalf;
  return (!s || s.turn !== state.turn) ? C.charges : Math.max(0, C.charges - s.used);
}

// 반감 후 값 — 실제 적용과 예상 결과가 **같은 함수**를 쓴다 (저RNG 원칙)
export function firstHitHalfValue(dmg) {
  return Math.max(BALANCE.damage.floor, Math.round(dmg * BALANCE.gimmick.firstHitHalf.mult));
}

// UI 표시용: 이 기믹에 '충전' 개념이 있으면 남은 수를 준다
export function gimmickCharges(state, unit, id) {
  switch (id) {
    case 'firstHitHalf': return firstHitGuardLeft(state, unit);
    default: return null;
  }
}

// 실제 적용(충전 소모 포함). 반환 { dmg, gimmickId }
function consumeIncomingGimmick(state, unit, dmg, kind) {
  if (!MITIGABLE_KINDS.has(kind)) return { dmg, gimmickId: null };
  const C = BALANCE.gimmick.firstHitHalf;
  // 반감해도 표시가 -0이 되는 구간에서는 소모도 연출도 하지 않는다
  if (dmg < C.minRawToTrigger) return { dmg, gimmickId: null };
  if (firstHitGuardLeft(state, unit) <= 0) return { dmg, gimmickId: null };
  const s = unit.gimmickState.firstHitHalf;
```

- 부수 사항: `PASS_CRITERIA`에 §5가 명시한 **난이도 보정(이지 +15%p / 하드 −15%p)이 코드화되어 있지 않다.** 지금은 easy/hard에도 노말 기준이 그대로 적용된다. 이걸 넣으면 `sword/easy`·`sword/hard`의 판정이 달라진다.

### ② §3-4 "마왕군 5종에 광역기 1개씩"이 3종만 달성된다 — 계획서와 모순, 승인 필요

해골 병사(반격 세금)와 암흑 주술사(마법사 주인공 보스전 99%→55%)는 실측상 광역기를 줄 수 없다. 계획서 문구를 "**실제로 발동하고 총 위협량을 올리지 않는 킷 보강**"으로 재해석해야 한다. 주고 싶다면 선행 작업이 필요하다:
- 병사: `applyDamage` 계열이 아니라 **반격 규칙**을 손대야 한다(예: 액티브 피격에도 감쇄 반격 허용 = 작업계획 §3-2 B/C안 영역). 이번 범위 밖.
- 주술사: `ai.js` support 분기를 "버프 스킬 전부를 순회하며 유효 대상이 있는 첫 스킬을 고르는 루프"로 일반화하고 힐/버프보다 광역을 우선하는 조건을 넣어야 한다. 콘텐츠 하드코딩은 아니지만 AI 정책 변경이라 별도 승인 대상.

### ③ 무덤의 한기는 보스 전용 콘텐츠다 (일반전 발동 0회)

`undead_squad`에서 0.00회/판이다. guard 분기가 T1에 반드시 도발을 걸고, 도발이 파티 화력을 기사에게 강제해 T2 전에 죽기 때문이다(HP 30). 보스전에서는 1.94회/판으로 정상 작동한다. **일반전에서 "적도 광역기를 쓴다"를 가르치는 것은 궁수(뼈살 관통)와 살수(그림자 난도)가 맡는다.** 이 비대칭을 그대로 둘지, 망령 기사의 도발 쿨을 늘려 한기 창을 열지는 판단이 필요하다(쿨을 늘리면 보스전이 흔들린다).

### ④ 오토 행동 순서 — 시뮬 수치는 "오토 최악 순서" 끝값이다

[보스기믹] 검증이 측정한 대로, `AI.autoAction`에는 행동 **순서** 개념이 없고 항상 `livingUnits` 슬롯 순서로 때린다. 기믹의 플레이 표현력 전부가 "어느 인스턴스로 충전을 태우느냐"인데 오토는 언제나 최악 순서이며, 최적 순서 대비 격차가 그 턴 보스 총피해의 **15.5%**다. **이번 명세는 순서를 고치지 않는다** — 오토·소탕은 출시 기능이라 행동 순서 변경은 별도 승인이 필요하다고 판단했다. 대신 mustFix의 최소 요구를 지켜 명시한다: **보스전 6.28턴은 오토 기준 끝값이고, 수동 최적 플레이는 5.4턴대로 나온다.** 사용자 플레이 테스트 후 2차 조정 시 이 15.5%를 감안할 것.
