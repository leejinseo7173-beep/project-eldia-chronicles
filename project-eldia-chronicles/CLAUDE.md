당신은 지금부터 웹 게임 **「엘디아 연대기: 여명의 맹세」** (프로젝트명: eldia-chronicles)의 개발을 맡는다.
이 프로젝트의 단일 기준 문서는 같은 폴더의 **`기획서_엘디아연대기.md`**다. 작업 시작 전에 기획서 전체를 정독하라. 이 프롬프트와 기획서가 충돌하면 기획서를 따른다.

## 게임 요약
정통 판타지 수집형 JRPG. 아군 왼쪽·적 오른쪽의 팀 턴제 사이드뷰 전투(연계 협공이 핵심), 직접 걸어다니는 필드 탐험, 뽑기로 15명의 동료 수집, 방치 생산이 있는 왕국 재건, 호감도 교감. 비주얼노벨 방식 스토리. 한국어 게임. 코드 생성 픽셀아트 + Web Audio 칩튠으로 **외부 에셋 제로**.

## 절대 규칙 (위반 금지)

1. **기술 스택**: 바닐라 JavaScript(ES 모듈) + HTML5 Canvas. 프레임워크·빌드 도구·외부 라이브러리·외부 에셋 금지 (Galmuri 폰트 파일만 동봉 허용). 로컬 정적 서버로 실행.
2. **모든 밸런스 수치는 `src/balance.js` 한 파일에만** 둔다. 데미지 배율, 스탯 성장, 생산량, 비용, 드랍률, 확률, TTK 목표까지 전부. 다른 파일에 매직 넘버를 두지 마라.
3. **데이터 주도**: 캐릭터·스킬·적·아이템·스테이지·시설·스토리 텍스트는 `src/data/`의 데이터 파일로 정의한다. 콘텐츠 추가가 코드 수정 없이 데이터 추가로 되게 하라.
4. **로직·렌더 분리**: 전투 로직은 렌더링 없이 완결되는 순수 계산 모듈(`src/battle/logic.js`)로 작성한다. 오토 전투·소탕·자동 밸런스 시뮬레이터는 이 로직을 재사용한다.
5. **시드 랜덤**: 모든 랜덤(치명타·드랍·뽑기)은 시드 기반 RNG(`src/core/rng.js`)를 쓴다. `Math.random()` 직접 호출 금지.
6. **정수 연산**: 데미지·스탯 최종값은 정수.
7. 픽셀아트는 코드로 생성해 로드 시 오프스크린 캔버스에 프리렌더하고 재사용한다. 매 프레임 픽셀 단위 그리기 금지. 기준 해상도 960×540, 정수배 스케일링.
8. 조작은 마우스 완결 + 키보드 단축키 병행. 키보드만으로도 전체 플레이가 가능해야 한다 (추후 스팀 대응).

## 코드 구조 (기획서 17장과 동일)
```
index.html
src/
  main.js          # 게임 루프·씬 매니저
  balance.js       # 모든 수치
  data/            # characters, skills, enemies, items, stages, buildings, story
  core/            # save, rng, audio, sprites, input
  battle/          # logic, ai, simulator
  scenes/          # 화면 13종 각 1파일
  dev/             # 치트 콘솔
```

## 개발 순서 — 마일스톤 M1~M9 (기획서 17장)

반드시 이 순서로 진행한다. **각 마일스톤은 "플레이 가능한 상태"로 완결**하고, 아래 검증을 통과한 뒤 사용자에게 실행 방법과 확인 포인트를 보고하고 다음으로 넘어간다. 여러 마일스톤을 한 번에 진행하지 마라.

- **M1 코어**: 엔진 루프, 씬 매니저, 시드 RNG, 저장(localStorage+내보내기/가져오기), 타이틀 화면
- **M2 전투 프로토타입**: JRPG 사이드뷰 고정 진형, 캐릭터→액션→대상 선택, 일반공격·연계 협공·반격·대기, 2vs2. 예상 데미지 표시 포함. ★이 단계에서 전투가 재밌는지가 프로젝트의 성패다 — 손맛(가로 돌진·타격 플래시·팝업)까지 넣어라
- **M3 전투 완성**: 스킬(범위 5규격·쿨타임)·상태이상 14종·AI 5성향·별점·승리조건 변형·오토·2배속·치트 콘솔·자동 시뮬레이터
- **M4 필드+1장**: 탑다운 이동·채집·상자·심볼 인카운터·숨김길·1장 맵 2개·정령 제단
- **M5 거점·수집**: 거점 화면·시설 13종·방치 생산·인구·뽑기(천장·연출)·육성 4축·장비·인벤토리·상점·교감
- **M6 수직 슬라이스**: VN 대화 시스템·프롤로그 컷신·새 게임 흐름(난이도→주인공 설정→튜토리얼)·1장 스토리 완성
- **M7 콘텐츠 양산**: 2~5장+종장, 파밍 던전, 서브 퀘스트, 보스 6종 기믹, 엔드게임
- **M8 폴리싱**: BGM·효과음(Web Audio 칩튠), 밸런스 시뮬 튜닝, 최적화(60fps), 도감·업적
- **M9 패키징**: 단일 HTML 빌드 스크립트 + Electron 또는 Tauri 데스크톱 빌드(전체화면·파일 저장 전환)

## 마일스톤 공통 검증
- 자동 시뮬로 TTK 앵커 확인 (동레벨 일반 몹 = 딜러 2행동, 보스 5~8턴, 아군 피격 4~6대 생존)
- 세이브 저장→로드 왕복 후 상태 동일성
- 콘솔 에러 0, 60fps 유지
- 치트 콘솔로 해당 마일스톤 기능 전부 도달 가능

## 스토리·텍스트 집필 지침
기획서 2장의 스토리 뼈대와 4장의 캐릭터 한 줄 콘셉트를 근거로 **네가 모든 대사·퀘스트 텍스트를 집필**한다. 톤: 밝음 베이스 + 중요 국면의 진지함. 동료 간 대화는 유머러스하게, 4~5장은 묵직하게. 캐릭터 성격이 대사에서 드러나야 한다 (예: 에라는 자신만만한 말투, 테오는 느긋한 노인 말투). 존댓말/반말 관계 설정을 캐릭터별로 일관되게 유지하라.

## 미정 사항 처리 규칙
기획서에 없는 세부 사항(각성 진화 수치, 개별 몹 스탯, 맵 배치, 대사 등)은 **기획서의 원칙(TTK 앵커, 밸런스 안전장치, 톤)에 맞게 스스로 결정**하고, 프로젝트 루트의 `DECISIONS.md`에 "무엇을 왜 그렇게 정했는지" 한 줄씩 기록하라. 사용자에게 사소한 결정을 일일이 묻지 마라. 단, 기획서와 **모순되는** 변경이 필요하다고 판단되면 반드시 먼저 보고하고 승인받아라.

## 작업 방식
- 각 마일스톤 시작 시: 구현 계획(파일·기능 목록)을 짧게 보고 → 구현 → 자체 검증 → 실행 방법("npx serve 후 localhost:3000 접속")과 이번에 확인해볼 것 3~5개를 사용자에게 안내
- 커밋 단위: 마일스톤별 최소 1커밋 (git 사용 가능 시)
- 성능·가독성보다 우선하는 것은 없다: 동작하는 게임 > 이론적 완벽함
